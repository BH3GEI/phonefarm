copyprobe（08）把机制预演完之后，本步把 game_opt_loop 真实帧赛道的优胜算子
**gen1_loc3**（37.8dB / 0.479ms）按 candidate.spv 契约装进层，替换原神「渲染精度·低」

- 注入点：合成 pass（送显分辨率 2141×969）对渲染输出（1134×514）的 binding 0 采样。
  层建送显分辨率的输出图，dispatch 我们的算子，再把那一次采样的 binding 0 换过去。
- A 臂 = 挂层 passdump（只读追踪）+ 游戏自带放大；
  B 臂 = 挂层 upop（追踪开销一致，差值干净对应「算子替换」这一件事）。
- 负载：进大世界站定 36s 转视角（workload_spin_touch_v1），帧时 + 停充功耗（battery rail）+ 电池温度。

## 杂项记录

- **a5 作废**：原 a5 采到的是加载画面（fps=84.75、spf=1），作废后以 rerun5 对内交错补跑一对，上表用补跑值。
- **rust-port 污染核查**：lead 通报 rust-port 在持锁期间跑了一次 eval 冒烟，对手机施加
  `bus.DDR.boost_freq` 约 1–2s 后还原，自报时刻「15:20」。本批帧时臂 14:16–14:40 PDT、
  画质臂 14:56–15:45 PDT；15:20 按 UTC 读 = 08:20 PDT、按 CST 读 = 00:20 PDT、按 PDT 读落在
  纯截图作业段——**三种时区读法下均不与任何性能轮重叠**；且逐轮 snap_at_run/snap_after_run
  快照该旋钮全为 547000（空闲最小值）。结论：无污染，无轮次作废，仅记此一笔。
- **设置持久化教训**：「渲染精度」改动 force-stop 后不可靠存活，必须走优雅退出
  （派蒙→退出游戏→确认）落盘。本次还原（低→极高）已按此路径执行，并用 passdump 层复核：
  重启后 pass 表出现 2140×968 档、1134×514 档消失，确认「极高」已生效。层已关、游戏已停。
- **时辰对齐方法**：派蒙时钟面板单条 2500ms 顺时针连续扫（逆时针/分段会被弹回），
  三臂全部对齐到 ~11:57–11:59（正午光照漂移慢），截帧间隔内游戏时辰漂移 <1 小时，可比。
