# Phonefarm 研发与操作金科玉律 (Golden Rules)

本文档总结用户在项目演进中确立的所有核心原则、架构边界、设备管控准则、自动化目标与模型选型纪律。
后续所有设计、代码实现、测试运行与工程操作必须时刻严格对照本规范执行。

---

## 核心总目标 (The Overarching Goal)

phonefarm 是一套**通用**的设备自动化与实测基础设施：一个 Rust 内核、两种设备后端
（Android `adb` / OpenHarmony `hdc`），在同一套「设备抽象 + 记录契约 + 遥测 + 证据分级」之上，
并列承载多条互不依赖的上层能力——自主 UI 遍历、确定性脚本回放、一致性测试 harness、
端侧模型实测标尺、数据采集管线、设备农场运维、假设—实验—证据闭环、MCP 工具服务。

任何 App、任何游戏、任何测试套件都能操作，除少数强时间敏感场景外不做例外。
单一应用的特殊流程不属于核心目标，属于插件。

**视觉大模型只是其中一条上层通路，不是这个项目的定义。** 把 phonefarm 说成"VLM 遍历工具"
是把自己说窄了：`script` / `test-batch` / `cts-fetch` / `bench` / `capture` / `keepalive`
全程零 Token，不碰模型也各自成立。

### 零号铁律 · 其一：不变内核 + 并列上层

```
   run/benchmark/parallel/quest   script   test-batch/cts-fetch   bench   capture   experiment
                │                   │              │                │        │          │
                └───────────────────┴──────────────┴────────────────┴────────┴──────────┘
                                          │
              ┌───────────────────────────┴────────────────────────────┐
              │ 不变内核：设备抽象(adb/hdc) · 记录契约 · 遥测           │
              │           确定性纪律(三道检查/双重看门狗) · 证据分级     │
              └────────────────────────────────────────────────────────┘
```

- 上层各通路**互不依赖**：卸掉 VLM 通路，`script` / `test-batch` / `bench` 照常工作；反之亦然。
  任何"A 通路依赖 B 通路才能跑"的设计都是错的。
- **新增一条上层通路不应该修改内核**。若新通路迫使你改设备抽象或记录契约，
  先问这是不是内核缺了一条通用能力——是，就补进内核供所有通路共享；不是，就留在该通路自己层内。
- **遥测口径全局统一**：脚本局、CTS 局、VLM 局共用同一套遥测与同一套记录契约，
  因此可以横向对比。绝不为某条通路另开一套"专用遥测"。
- **判定纪律对所有通路一视同仁**：不确定就如实标注不确定（`NOT_RUN` / `ENV_BLOCKED` / 留空），
  绝不静默零记、绝不把跳过算成通过、绝不用默认值填补取不到的指标。

### 零号铁律 · 其二：不按专用来设计，专用场景一律是插件

- **核心层** (`src/universal/`, `src/runtime.rs`, `src/device.rs`) 只做通用能力：
  统一感知、统一动作协议、通用三大算子（弹窗确认 / 对白跳过 / 导航寻路）、优先级调度。
  核心代码**不得出现**任何具体应用的包名、界面文案、业务流程假设或特判分支。
- **插件层** (`src/plugins/`) 承载一切专用场景：某款游戏的剧情推进、某个 App 的特定业务流。
  插件通过 `universal::ScenarioPlugin` 契约接入，在优先级阶梯中占两档：
  `intercept` 抢在通用算子之前处理场景特有语义，`decide` 在通用算子放行后、大模型之前兜底。
- **判定标准**：新增一个专用场景，应当只在 `src/plugins/` 下新增模块并登记，核心代码一行不改。
  若某需求迫使你修改核心去迁就单一应用，那是设计错了，应改为插件。
- 卸下全部插件后，核心必须仍能独立工作，行为与插件化之前完全一致。

### farmagent 的定位必须是全自主闭环：
- **流程推进**：识别对白/字幕/分支卡片，自主注入确认动作推进并选择分支；
- **目标交互**：巡视视野内可交互标记，自主对齐并触发交互；
- **导航与脱困**：遇远距离目标或阻碍卡死时，自主寻路脱困，绝不依赖人工干预。

以上三项能力由核心通用算子提供，具体场景的识别特征由该场景的插件补充。

## 一、 设备生命周期编排 (PC 侧控制)

生命周期分两级，别混为一谈：

- **农场级**（`phonefarm keepalive`，规格 `docs/SPEC_KEEPALIVE.md`）：只要设备挂在农场里，
  就该醒着、解着锁、不息屏。这是通用能力，adb 与 hdc 两族并列实现，不属于任何插件。
  挂机设备会息屏、重新上锁、不息屏配置被系统组件冲掉，导致后续任何通路开局先死在黑屏上——
  这一级负责把待命期兜住。
- **任务级**（各上层通路自管）：进任务常亮、退出锁屏保电池。下面第 1~3 条是长跑 Agent
  （`quest`，原神插件）的任务级实现，其中手柄注入属插件专有，唤醒/解锁/锁屏属通用原语。

1. **按需拉起**
   - Agent 启动时，由 PC 端发出标准幂等唤醒指令（`input keyevent 224` 并滑动解锁），唤醒并确保目标应用在前台。
   - 若目标应用未运行，由 PC 端执行冷启动。目标包名由插件声明（如原神插件的 `PACKAGE`），核心不持有。

2. **免侵入流式注入**
   - PC 端在内存中启动 `adb shell hid -` 标准管道，建立虚拟 Xbox 手柄连接。
   - 所有按键（A/B/X/Y/LB/RB）、连续摇杆推杆（360度走位与视角旋转）、线性扳机（LT/RT）、十字键均通过 PC 端标准输入流式下发。
   - 严禁在手机写入常驻守护进程、FIFO 管道或 `service.d` 自启脚本，手机端零文件残留、零常驻负担。

3. **按需收尾与自动锁屏 (强制 Kill 后锁屏)**
   - 任务完成或退出时，PC 端主动断开手柄标准输入（系统自动注销虚拟设备，手机端零进程残留）。
   - 强制杀死目标进程：`am force-stop <插件声明的包名>`（杜绝游戏手机息屏保活黑屏挂机耗电与烧屏）。
   - 下发标准幂等休眠键将手机恢复锁屏状态（`input keyevent 223`，严禁使用会翻转亮屏的 keyevent 26）。
   - 平时保持黑屏待机，反复进入游戏与冷启动是 Agent 必备的核心能力。

## 二、 Agent 全自主剧情与非战斗任务闭环 (原神插件 `src/plugins/genshin.rs` 的场景实现)

Agent 在 PC 端通过纯 ADB 截图执行高频轻量图像分析，完全不依赖人工干预，覆盖以下三大自主行为：

1. **剧情自动快速推进与选项抉择**
   - 侦测底部字幕对话框与右下角技能栏状态（判定处于剧情会话）；
   - 以 ~300ms 节奏连续注入手柄 A 键推进对白；
   - 侦测右侧分支选项卡片（◆），自动选中并确认推进剧情分支；
   - 遇过场动画（CG / 黑屏加载）自动静默等待，直至场景重现。

2. **NPC 与目标交互自主触发**
   - 侦测视野内的交互标记（如 [X] 提示、NPC 名称、调查/机关点）；
   - 自主注入 X 键发起对话或触发机关，无缝衔接进入剧情模式。

3. **任务导航与自主脱困机制**
   - 当任务距离较远或处于水面/障碍卡死状态时，Agent 自主通过地图/任务追踪界面定位最近的传送锚点并触发传送；
   - 传送落地后，根据屏幕任务指引图标（菱形目标标）利用右摇杆对齐视野方向，左摇杆向前奔跑推进，自主接近目标触发点。

## 三、 视觉模型选型与系统负载纪律 (Model & Resource Discipline)

1. **极度节约，拒绝浪费 (最廉价模型原则)**
   - 严禁使用高昂成本的模型跑高频流水线。
   - 优先选择最廉价乃至完全免费的视觉与动作决策方案。
   - **但"最廉价"按单位任务的真实代价算，不按标价算**：标价为零却跑不对的通道并不省钱，
     它把步数预算烧在错误动作上、失败后还要把后续 provider 的配额一起赔进去，最终整局跑挂。
   - **排序必须用"真实截图 + 真实提示词"的同口径实测**，不能用 `/v1/models` 探活代替：
     硅基流动探活 0.24s，实际带图推理却要 36s，两者差两个数量级。
   - **首要指标是计划正确率，不是延迟**：一次错误的多步计划要花好几步去纠正，比慢几秒贵得多。
   - **纯 OCR 模型不得进决策链**：PaddleOCR-VL 一类模型只提取文字、产不出 act 记录，
     排在链上会每步白费一次调用。OCR 属于感知通道（`--perceive ocr`），不是决策通道。
   - 把测得的数字连同日期写进 `phonefarm.toml` 注释，换网络环境时据此重新调序。

   2026-09-07 本机同口径实测（60KB 截图 + 单轮视觉问答，各 3 次）：

   | 通道 | 带图调用耗时 | 成功率 | 计划质量 |
   | :--- | :--- | :--- | :--- |
   | `glm-5.3-flash` | 2.9-4.5s | 3/3 | 差：8 步任务的分批顺序会错乱 |
   | `openrouter minimax-m3:free` | 8.3-28s | 2/3 | 好：能正确拆成 `[1,2,8,+][2,5,6,=]` |
   | `siliconflow Qwen3-VL-8B` | 36-37s | 2/3 | 偏慢，仅作后备 |

   故当前次序为：openrouter-minimax（唯一跑通过整局）→ glm-53-flash（快速兜底，
   出错由 runtime 驳回与复核机制纠偏）→ openrouter-free → siliconflow → glm-vision。

2. **端侧本地轻量模型优先 (2B ~ 4B VLM)**
   - 在宿主机（Apple M4, 16GB 统一内存）部署轻量多模态模型（如 Qwen2.5-VL-3B / Qwen2-VL-2B / Moondream via Ollama 或 MLX）。
   - 严格注意系统占用，控制内存与显存消耗在 2.0GB ~ 2.5GB 以内，绝不拖垮电脑。
   - 本地模型享有零 Token 费用、零网络延迟，用于高频画面理解与状态分类。

3. **云端廉价模型兜底**
   - 智谱 BigModel 渠道：采用 Coding 套餐下的 `glm-5.3-flash`（极度廉价）或 `glm-4.6v`，显式配置 `thinking_disable = true`，严禁产生冗余 Reasoning Token 浪费资费。
   - Kimi 渠道：备用快速多模态编码模型（`kimi-k2.7-code`），仅在深层复杂决策时按需调度。
   - 密钥仅存本地 `secrets.env`，严禁入库。

## 四、 研发工程规范与工作流铁律 (Engineering & Workflow)

1. **代码是给人看的，只是机器恰好可以运行**
   - 追求优雅架构、清晰语义、模块化与完备注释。
   - 严禁堆砌无推导依据的魔法数字与粗糙硬编码。

2. **端到端验证绝不妥协，且每条上层通路各有各的验收口径**
   - 严禁以 1 分钟快速脚本冒充 30 分钟长测；严禁拿单测全绿冒充端到端跑通。
   - **长跑类**（`quest` / `run --endless` / `script --repeat`）：实机上跑满完整真实的 30 分钟连续运行，
     收集全量遥测，证明进程无泄漏、输入通道零掉线、指标曲线稳定。
   - **一致性测试类**（`test-batch` / `cts-fetch`）：用真实测试套件跑一轮，逐用例判定必须与官方结果对得上；
     失败用例必须带完整断言栈；未交代的用例必须如实对账成 `NOT_RUN` / `ENV_BLOCKED`。
     Android 与 OpenHarmony 两套协议各验一遍，不能只验一边就宣称双协议可用。
   - **标尺类**（`bench`）：判定口径（全图 GPU 无回退、离散度、时延阈值）必须每条都实测命中，
     不能只看退出码。异常退出后必须确认锁频态已回滚。
   - **纯离线改动**（解析器、报告格式、CLI）：`cd src && cargo test` 全绿是下限，不是上限；
     涉及协议解析的必须补上真实设备输出的样本作单测夹具。
   - 发现问题 → 修复 → 再次跑满对应口径验证 → 整理代码与文档 → 提交 PR 并合并至 main。

3. **构建后必须重新签名 (Apple Silicon 硬性要求)**
   - `[profile.release] strip = true` 会在链接后剥离符号，**使 Rust 附加的 ad-hoc 代码签名失效**。
   - 失效的二进制在 macOS 上不会报错，而是**静默卡死在 `_dyld_start`**（进程存活、CPU 为零、无任何输出），
     极易被误判为程序逻辑死循环或设备失联，代价高昂。
   - 因此构建流程固定为：`cargo build --release && cp target/release/phonefarm .. && codesign --force --sign - ./phonefarm`。
   - 跑任何实机端到端测试之前，先确认用的是当前源码构建并已签名的二进制，避免拿陈旧产物的行为当作代码结论。

4. **及时 Commit，定期 PR**
   - 阶段性成果（模块重构、Bug 修复、基础设施扩展）必须及时进行语义化 Git Commit，严禁大范围修改无序积压。
   - 保持小步快跑与定期 PR，确保代码变更历史清晰、可追溯、可独立评审与安全回滚。

5. **Root 权限边界**
   - Root 仅用于只读性能遥测（CPU/GPU/内存/温控/I/O），严禁在手机硬写持久化服务。
   - 锁屏密码已通过 Root 移除并禁用锁屏，确保无密码阻碍。

## 五、 交互与沟通规则 (Communication Style)

1. **绝对禁用 Emoji**：所有助手输出、代码注释、控制台打印信息一律严禁使用任何表情符号。
2. **思考与语言**：思考过程必须使用英文（Think in English），与用户的交流和汇报必须使用清晰严谨的中文。
3. **如实汇报与严守底线**：实事求是，严禁弄虚作假或偷工减料。
