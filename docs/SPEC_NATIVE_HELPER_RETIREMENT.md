## Finite support matrix

This new contract supports only the existing native preinstall/helper-only
session: no main_install/inputs/sample/control intent, exactly original
render_initial master and at most one registered render_reader child, known
complete launch/permit state. Existing worker/bootstrap/collector/native
artifact bytes remain identical to518/f889; no legacy session is relabelled.
Live/reused/missing-epoch, orphan group, unbound launch, unknown source, unknown
phase or changed boot/token remains UNKNOWN. This version grants no live stop
or generic repair authority and changes no20s remote/30s transport deadline.

`diagnose-helper-native --session S --execute` keeps the same recovery barrier.
`retire-helper-native --session S --execute` explicitly retires only a proven
dead helper phase. Both validate current complete preinstall/native/source/state/
intent bytes and take the existing recovery lease for exact S/target, not a new
namespace or normal lease. No caller PID/path/source-body/threshold is accepted.
No model call or device performance experiment is part of the operation.

## Native process proof

Before executing any native helper, freshly read/verify the actual fixed five
remote files and executable bit against the frozen local artifact, plus exact
owner/boot. The host sends its fixed source through supervised stdin. It uses
the unchanged verified read-only native reader to ingest NUL triples for a
complete bounded /proc PID stat inventory, current actor stat, boot before/after
and inventory count. Maximum1024 PID directories (below reader2048request cap),
per stat4096bytes, aggregate2MiB. No per-PID head/sed/awk fork. Missing/racing/
malformed/oversize entries or missing native terminal marker refuses completion;
unknown entries are never silently discarded. Metadata snapshots are not source
or process lifetime attestation.

Both recorded leader and child PID must be absent from a complete current
snapshot; any present PID, including a different epoch, refuses retirement.
All their PGIDs must also be absent from the complete stat inventory AND a
root/kernel negative-group signal0 check must yield the same explicit ESRCH
condition as the original worker. Permission/error/ambiguous output refuses.
Old registered groups receive only signal0. A new native child that has not been
reaped may be killed on this operation's failure only after its durable
PID/start/PGID and current epoch match; this operation is its parent, so its PID
cannot be reused before wait. An unbound child remains UNKNOWN. No deadline
increase is used. The frozen same-boot
negative proof is checked again before mutation; a later uncertainty retains
the barrier. This is not a substitute for the existing general worker recovery
or control/trace restoration.

## Bounded retirement transaction

The host first creates a durable single-operation intent binding exact original
state/preinstall/helper intent, fixed source/native byte hashes and a unique
retirement run ID. The remotely supervised actor records its own PID/start/PGID
under that same session before mutation. It never resumes/launches the old
worker or reader workload. Only after all registered old actors/groups are
absent and no unbound pending launch exists may it create the helper's permanent
session.closed tombstone, retire the exact matching stale master lock, and emit
bounded phase receipts. Old app controls/ftrace are not touched.

Removal is a separate verified step: exact same owner/boot/closed run receipts,
all old and newly registered actors/groups absent, current root path identity,
and a fixed helper-only inventory are required. Remove only this owned helper
directory; verify the path is currently absent. Only then may the existing
Lease.complete_recovery clear its local barrier. Any partial/error/interruption
retains it. A recorded transaction may only reconcile its explicitly bound
phase/receipts, never guess idle or adopt an arbitrary directory/PID. Success is
HELPER_CLOSED_REQUIRES_NEW_SESSION, eligible/game/promotion/control_restore=false;
failed old samples are not validated or reused. Main-phase sessions must use
existing full restoration.

## Explicit interruption boundary

This first version does not adopt/retry a partially recorded new transaction.
Every phase has a unique remote directory and create-only host intent; an
UNKNOWN operation retains the barrier and its ledgers. A fresh operation
rejects those unregistered remote directories. Closing/removal run separately,
and each successful phase is followed by a synchronous fixed system-only
negative PID/group checker; it launches no background group or native worker.
The complete native table is required before each mutation; final absence
checks also include all recorded operation actors/children. Final checks are
same-boot endpoint proof, not an assertion that local ADB completion stops
remote work or that processes can never subsequently appear.

The removal source additionally embeds exact SHA256 of the prior actor/child
ledgers reconstructed from the completed close stdout; that stdout and new
source are frozen transport inputs. Both native receiver and pre-delete kernel
checks reject any original or close-phase PID/group. The session tombstone
contains only a regular owner file. The prior close directory has exactly ten
registered entries (nine regular files plus start.pipe FIFO); extra/linked
content rejects removal. A create-only single-operation local intent prevents
resubmitting either a successful or UNKNOWN new transaction.

Each stat is accepted only at <=4096 bytes. The unchanged reader's physical
file reader remains bounded at 64KiB; its aggregate2MiB output and mandatory
terminal must complete before table acceptance. Overflow/partial output never
proves any PID/group absent.

A final independent check specifically preserves CLOSE_NP separately from the
current phase native PID. Both are checked immediately before deletion, after
printing the native snapshot. A prior close PID or its group appearing after
the complete table is still UNKNOWN and must leave the owned directory intact.
Actual host counterexamples register that late PID/group after native stdout;
old10710 incorrectly removed the directory, new source rejects removal.
