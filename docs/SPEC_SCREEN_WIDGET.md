## 0. 它解决什么

自动化跑起来之后看不见设备是最难受的一件事：局在跑，你只知道它在跑。
这个窗口把「设备现在长什么样」和「harness 刚才点了哪」放在同一张图上。

```bash
phonefarm screen [--serial <设备>] [--port 8899] [--interval-ms 700]
                 [--actions <log.jsonl>] [--from-start] [--out <目录>]
```

---

## 1. 三条纪律

| 编号 | 纪律 | 落点 |
| --- | --- | --- |
| SW-1 | **只读**。不改设备状态，也不拿设备锁 | 拿锁就没法在别人跑局时观战，而观战正是它的用途 |
| SW-2 | **但它不是免费的**。每秒一次 `screencap` 会动 GPU 与 CPU，**做判定性测量时不要开着它** | 这条同时写在 `--help`、页面正文、`src/screen.rs` 文件头 —— 三处都写，因为它是这条路上唯一会伤到别的东西的行为 |
| SW-3 | **不重放**。流断了就如实显示「断开」并继续重试取帧，不补历史帧 | 看到的就是当下 —— 与 `collect` 的不重放同源 |

SW-1 与 SW-2 是一对：因为不拿锁，所以它可能和别人同时碰设备；因为可能同时碰，
所以把「它会扰动测量」写在最显眼的地方，而不是靠锁去回避。

## 2. 取帧

```
adb exec-out screencap -p  →  PNG 解码  →  缩到 672 宽  →  JPEG(质量 85)
```

与 `capture` 同一条通路、同一个缩放口径 —— 观战看到的和归档存的不是两个东西。

- 间隔由 `--interval-ms` 定，**下限 200ms**。再密就是拿设备当靶子打。
- 设备离线 / 被别的进程占着 / adb 不在 PATH：如实把原因写进 `/state.json` 的 `error`，
  页面显示「断开」，**不显示上一帧冒充直播**（缓存会保留，但页面加了 `stale` 样式把它变灰）。

## 3. 动作叠加

`--actions <log.jsonl>` 尾随一份局记录，把 `{"r":"act",...}` 记录画成点击/拖动提示。

| 规则 | 说明 |
| --- | --- |
| **坐标在服务端归一化** | 设备像素 → 0~1。页面不猜缩放；换个分辨率、换个前端都不用改 |
| **越界坐标夹紧** | 设备换了分辨率、或坐标来自另一台机时，不能画到框外去 |
| **只收动作记录** | `r != "act"` 一律不进；没有 `a` 的也不进 |
| **环形有上限** | 保留最近 64 条。长时间观战不能吃内存 |
| **`since=` 是严格大于** | 拿最后一条的 `seq` 再问，必须拿到空 |

默认**实时**（从文件末尾开始跟）。要看已经跑完的局，加 `--from-start`。
文件被换过（新的一局）时从位置 0 重读 —— 不追旧文件的位置。

## 4. HTTP 接口

| 方法 | 路径 | 返回 |
| --- | --- | --- |
| `GET` | `/` | 自包含 HTML（服务端把配置注入 `<head>` 之后） |
| `GET` | `/frame.jpg` | 最新一帧 JPEG；还没有帧时 `503` |
| `GET` | `/state.json` | 设备序列号、分辨率、已取帧数、暂停态、间隔、最后一帧时间、错误 |
| `GET` | `/events.json?since=N` | `seq > N` 的动作事件 |
| `POST` | `/screenshot` | 把当前帧写到 `--out` 目录，返回路径 |

std-only，不引 HTTP 库：路由就这几条，一个 `BufReader` 加一个 `write_all` 够了。
`--port` 绑 `127.0.0.1`，不监听外网。

### 页面是自包含的

单文件，无外链、无 CDN、无构建步骤（单测钉死：不得出现 `http://` / `https://` /
`<script src`）。观战窗口要能在没有外网的设备网里开。

## 5. 尚未落地

- **iOS 的观战**：`phone.screen` 走的是 adb。iOS 后端有 `screen()`（WDA 截图），
  接进这条流是下一步 —— 现在 `phonefarm screen --serial ios:…` 会走 WDA 的截图通路，
  但它没有真机验证过（见 `docs/DEVICES.md`）。
- **多设备同屏**：现在一个进程一台设备。看板要同时看几台，得再起几个端口，
  或者在本层做一个多设备的聚合面。
- **它的代价没有被量化**：SW-2 说「会影响帧时与功耗」，但没有实测过影响多少。
  在把它当成「无害的观战」之前，应当先量一次。
