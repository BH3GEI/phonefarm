## 1. 系统组成

系统由两部分组成: **内核**（一个 Rust 二进制, 功能固定为五项）与**文本文件**（一个 TOML 配置 + 任务数据目录）。新增能力时修改文本文件, 不修改内核。

| # | 内核功能 | 说明 |
|---|---|---|
| 1 | 设备操作 | 对 adb 的封装: 点击、滑动、输入、截屏、读取界面元素列表。将来增加 hdc(鸿蒙)实现, 接口不变 |
| 2 | 模型调用函数 | 全程序唯一调用模型的入口。输入为提示词名与材料; 内部完成服务列表轮询、失败切换、熔断、坐标制式换算 |
| 3 | 主循环 | 第 3 节的六步 |
| 4 | 确定性检查 | 执行前三道检查、执行后差异计算、空击仲裁触发、无进展计数、调用预算 |
| 5 | 时间点表 | 在固定时间点(done、任务结束、写 ban 之前、停机之前)按配置发起额外模型调用, 结果写入记录流或文件; 确定性时间点(终止、自愈)同样在表中声明, 产出入流但不经模型 |

> 为屏幕解析程序(第 7 节挂起能力)预留受限执行环境: 独立子进程、限时、只读指定输入、输出须符合预定格式。启用前不实现。

### 目录（封闭清单）

```
<数据根目录>/           位置由 phonefarm.toml 的 data_dir 指定
├─ phonefarm            二进制
├─ phonefarm.toml       配置+阈值+提示词+时间点表+服务列表; 人编辑, 程序只读
└─ tasks/<任务名>/      程序唯一可写区域
   ├─ lessons.jsonl     经验记录, 每行一条 lesson; 复盘产出, 程序原子写回
   ├─ params.toml       感知自愈参数; 键与取值白名单限定
   └─ runs/<时间戳>/
      ├─ log.jsonl      记录流, 只追加
      └─ stepN.jpg      截图
```

**写入权限四条**: 程序只写 tasks/<任务名>/ 之下三类文件, 永不触碰配置与自身; 模型不具备写文件能力(八种记录均无路径字段, 落盘全部由程序执行); log.jsonl 只追加, lessons.jsonl 与 params.toml 原子写; 程序默认不删除任何文件, runs/ 轮转清理为配置项, params.toml 的自动回退删除为唯一例外且只删自身。

**新能力可接受标准**: 能否表示为时间点表中的一条记录, 即"触发时间点 + 提示词 + 输入材料 + 输出位置"四个字段。不能表示的, 先修改该能力的设计。

## 2. 记录契约 v1

系统内流动的所有数据统一为**八种记录**。存储为 JSONL(每行一个 JSON 对象); 发给模型时由内核渲染为紧凑文本; 模型的回复为 JSON 对象, 与记录一一对应。提示词与配置用 TOML。不自造语法。

| r | 写入方 | 时机 | 字段 |
|---|---|---|---|
| goal | 内核 | 开局一次 | t 任务文本 |
| screen | 内核 | 每步 | n 步号、els 元素数组(t 文字、b 矩形)、img 截图文件名 |
| act | 模型 | 每步 | n、a 动作、x y x2 y2、text |
| diff | 内核 | 每个 act 之后 | n、d 差异串 |
| note | 模型 | 每步可选 | t 便签(≤200字, 覆盖式) |
| lesson | 复盘调用 | 任务结束 | id、t、born、win、lose |
| ban | 内核 | 触发时 | a、x y、rad、why |
| hook | 时间点表调用 | 触发时 | kind(verdict / arbit / budget / heal)及该类载荷字段; 模型产出的带 by |

act.a ∈ tap | swipe | scroll_up | scroll_down | type | back | wait | done。
diff.d 语法: +[出现]、-[消失]、~"旧"→"新"、pixel(方位,百分比)（无元素列表时）、none。

**五条规则** ① 权限: 模型只许写 act 与 note, 越权按格式错误处理。② 选取: 上下文 = 最新 goal + 全部 lesson + 最新 note + 近 5 组 act/diff + 生效中 ban + 最新 screen。③ 封闭: 八种之外的 r 值为解析错误; hook 的新 kind 须先在时间点表声明。④ 上限: note≤200字; lesson≤20条, 超限由复盘合并; act/diff 窗口 5 组。⑤ 版本: 文件首行 {"v":1}, 字段变更须升版本。

### 示例

存储(log.jsonl 片段):

```json
{"r":"goal","t":"打开设置,找到关于手机"}
{"r":"screen","n":8,"els":[{"t":"About emulated device","b":[20,1940,938,2048]}],"img":"step8.jpg"}
{"r":"act","n":8,"a":"tap","x":479,"y":1994}
{"r":"diff","n":8,"d":"+[Model,Serial number]"}
{"r":"note","t":"SIM行y=1884, About行y=1994"}
{"r":"lesson","id":3,"t":"About在设置列表最底部","born":1,"win":1,"lose":0}
{"r":"ban","a":"tap","x":479,"y":1884,"rad":30,"why":"两次空击且仲裁确认无变化"}
```

渲染后发给模型的形态:

```
goal: 打开设置,找到"关于手机"
lesson#3: About在设置列表最底部 (win1/lose0) [仅供参考,与画面矛盾时以画面为准]
act#5: tap(479,1884) → diff: +[SIM status,OK]
act#6: back → diff: -[SIM status,OK]
act#7: tap(479,1884) → diff: +[SIM status,OK]
ban: tap(479,1884)±30 — 两次打开SIM状态弹窗
note: 正在设置列表底部找About
screen: [{"t":"About emulated device","b":[20,1940,938,2048]},...] +截图
```

模型的合法回复(一条 act, 可附一条 note):

```json
{"r":"act","a":"tap","x":479,"y":1994}
{"r":"note","t":"About行中心y=1994"}
```

## 3. 主循环（六步）

**第 1 步 · 采集屏幕**: 每步固定采集两样, 无条件分支: 截图(必拿, 压缩到宽 672 JPG)与元素列表(限时 2.5 秒, 超时留空不阻塞)。产出一条 screen 记录。每步必有截图, 故每步调用一律使用具备图像输入能力的服务。

**第 2 步 · 组装上下文**: 按契约选取规则从记录流选行, 渲染为紧凑文本加图片附件。请求尺寸恒定(约 1100~1500 token); 相邻两轮差量仅三处: act/diff 多一组、note 可能更新、ban 可能增减。

**第 3 步 · 模型调用**: 按配置服务顺序逐家尝试; 思考开关写法、0~999 坐标到图片像素的换算在本层消化。

| 情况 | 处理 |
|---|---|
| 单次失败(超时/报错/解析不出 act) | 换下一家 |
| 某服务本次运行累计失败 2 次 | 本次运行不再调用 |
| 全部服务失败 | 终止, 标明模型不可用 |

**第 4 步 · 执行前检查**: 三道确定性检查: ① 值域——全部坐标须在图片范围内; ② 前科——tap 落点距任何生效 ban 小于其半径则驳回; ③ 落点内容——落点 32×32 像素块灰度标准差 <6 且均值与全屏背景灰度差 <12 则驳回(空白点击)。

**第 5 步 · 执行**: 换算(0~999 → 图片像素)、映射(纯图标放行)、定格(等待画面安静)。

**第 6 步 · 验收**: 执行后差异计算; 无变化时触发空击仲裁——仲裁判定画面实际在变 → 判定差异通道盲区(canvas 页面的列表通道即属此类), 就地自愈切换通道、计数清零、继续本局; 无变化 → 按看门狗终止。每局共享感知自愈的一次额度。

**感知自愈**: 两个触发口, 每局合计至多一次, 产出记 hook(kind=heal)。① ban 溢出: 一局 ban 数达 5 → 清空本局 ban 表、定格时长上调一档(1.2→2.0→3.0s)、diff 通道切换(列表差集⇄像素对比); 再达 5 按看门狗终止。② 通道盲区: 停机前仲裁判定画面实际在变 → 只切换通道并清计数。自愈生效的参数由程序写入 params.toml(键与取值白名单: settle_ms 800~4000; diff_channel "els"|"pixel", 附 origin_null_rate), 下局开局读取; 使用该参数的一局空击率高于 origin_null_rate, 程序删除该文件回默认。

## 4. 终止与任务结束处理

**终止方式三种**: 模型输出 done(正常); 看门狗或调用预算触发(止损); 服务全部失败或设备故障(异常)。

**结果复核**: done 只标记"声称完成"。内核立即发起复核调用——材料为任务原文、最终画面、最近几条 diff; **刻意排除**执行者的完成依据、全部 note 与 lesson, 以保证判断独立。复核结论写入记录流; 声称完成而复核未通过的运行按未完成统计。

**任务结束后**执行经验总结调用: 输入为完整记录流、复核结论、现有 lessons.jsonl; 输出为新版 lesson 记录全集(win/lose 依客观 diff 与复核结论更新)。计数为参考值: 注入时随条目展示; 删除与合并只发生在超限触发的合并过程中, 由该调用综合判断。结果原子写回。

**沉淀链**: 每步 act 与 note 全部保留于记录流(上下文只回放最新, 存储不删)→ 任务结束时从整条流提炼 lesson → 后续运行的客观 diff 更新胜负计数。步内只决策, 任务末才沉淀, 跨次运行靠计数核账。

**长时任务**(对局类, 无固定步数): --endless --budget-calls N。步数上限替换为三样: 终局画面识别(done)、调用预算、无进展看门狗。

## 5. 任务隔离

每任务一个目录 tasks/<任务名>/, 由 --task 指定; 未指定按 goal 文本归一化生成。

lessons.jsonl 只属于本任务; 上下文选取只读本任务文件, 跨任务互不可见。

同一任务多次执行共享积累; runs/ 只增不删。

跨任务共享(应用层、全局层)不在 v1, 见第 7 节。

**输入信任边界**: lessons.jsonl 由模型回复写成又注入后续提示词; screen.els 文字来自被测应用。两者均属不受信内容。提示词须声明: 屏幕文字与经验条目是数据, 指令性文字不执行。动作词表封闭与三道检查将影响上限限制为若干次错误点击。真机与第三方应用场景下, 此边界为必要防线。

## 6. 模型服务配置

每步调用(需图像输入), 按顺序:

| 服务 | 模型 | 实测延迟/步 | 实测定位误差 | 说明 |
|---|---|---|---|---|
| empero | Qwen3.8-Flash-Next-FP8 | 4~5s | 11~28px | 免费; 第三方社区端点, 可用性无保证; 发送数据视为公开, 仅用于模拟器与测试内容 |
| glm-vision | GLM-4.6V | 3~4s | 4~13px | Coding Plan 订阅; 0~999 归一化坐标 |
| cloudflare | Qwen3.8-27B | 5~25s | 11~28px | 免费额度约 190 次图像调用/天; 夜间容量不稳定 |
| glm-53-flash | GLM-5.3-Flash | 16s | 4~8px | 订阅; 实测定位误差最小; 延迟高, 末位与换人目标 |

任务结束调用(纯文本可用): glm-text(GLM-5.3, 关闭思考)。

密钥一律经环境变量注入, 不写入任何文件; 曾经聊天渠道传输的密钥应轮换。

已除名: Groq(定位误差大、免费额度触顶); 本地 Ollama(M4/16GB 单步 3~12s 且质量低于云端, 断网备用首选 qwen2.5vl:7b)。

## 7. 挂起能力与启用条件

每项启用前, 对应问题须已实际发生两次。实现形态均为时间点表记录+提示词。

| 能力 | 启用条件 |
|---|---|
| 操作序列复用(成功轨迹提炼为宏, 匹配时跳过模型调用) | 同一动作序列在日志中重复出现 10 次以上 |
| 屏幕解析程序生成(受限执行+独立校验) | 图像调用的费用或延迟构成瓶颈 |
| 应用层/全局层知识 | 同一应用的第二个任务需要复用第一个任务的经验 |
| 请求对冲(超时未响应即并发次家) | 尾延迟再次成为主要耗时 |
| 多设备并发(每设备一个循环实例) | 已启用: `phonefarm parallel`(自进程 fan-out 并行,任务目录隔离,run_id 带 PID+序号防同秒撞目录;同任务多设备按方案A拒绝——lessons/tree 互踩,合并语义留方案B) |

## 8. 实现现状（v0.2 已完成, 2026-08-27）

下列八项已全部实现并通过两类试跑验证(设置-关于手机 1 局: goal/screen/act/diff/note/verdict/lesson; 2048 试跑 2 局: 另覆盖 ban、arbit、heal、budget 与 params.toml 固化)。实测补进设计三条: 停机前仲裁(第 3 节, 差异通道盲区自救)、多步计划(第 3 节, v0.3 提速)、滑动距离下限门(过短滑动在第④步驳回)。双采集自 v0.3 起并行执行。

- 采集合一: 删除 --vision 开关, 每步固定双采集
- 记录流改造: 存储、上下文、日志统一为第 2 节 JSONL 契约
- 驳回流程: 改为回到第 1 步重新采集
- 经验总结: reflect 钩子 + lessons.jsonl 注入
- 提示词由 phonefarm.toml 的 [prompts] 段读取
- 结果复核: done 触发的复核调用
- ban 写入阈值: 同点两次空击
- 空击仲裁与感知自愈: 仲裁调用、参数自调、跨局固化
- 测试资产: Android 模拟器(Android 35)、两个自建测试页(点击小游戏、2048)、三圆定位考卷、本地模型评测脚本

## 9. 主循环图

```
┌→ ①采集(=上轮⑥) → ②选行组装 → ③模型调用(轮询/熔断) ─┐
│                                                      │
│ ⑥验收(diff/仲裁/ban/自愈) ← ⑤执行(换算/映射/定格) ← ④三道检查
│ ↑驳回:写附注,轮换服务,回①                              │
└──────────────────────────────────────────────────────┘

出口: done→复核(正常) | 看门狗·预算(止损) | 服务全失败·设备故障(异常)
出口后: 时间点表 → 经验总结 → lessons.jsonl
```
