> 状态: 定稿 v1 · 本 PR 新增

> 适用范围: 所有「把设备画面喂给模型」的通路 —— 目前是 VLM 自主遍历(`phonefarm run` /
> `benchmark` / `quest`)。`script` / `test-batch` / `bench` / `capture` / `collect` 属于零 Token

## 0. 这份契约解决什么

闭环的最大成本不是设备时间, 是**模型调用**。每一次调用都要把「当前画面是什么」塞进上下文,
而画面的原始形态(完整 XML + 全分辨率截图 + 每步历史)是 O(步数) 增长的。

本契约规定: **进模型上下文的东西必须有界、且这个界必须看得见**。
三件事不许含糊 —— 折了什么、剩多少预算、停在哪。

## 1. 硬约束(违反即视为回归)

| 编号 | 约束 | 现状 |
| --- | --- | --- |
| OB-1 | **原始 XML 永不进上下文**, 只落盘(`stepN.xml[.gz]`), 上下文里只留文件名 | 已实现: `runtime.rs` 采集时写盘, 记录里只放 `xml_rel` |
| OB-2 | **单屏元素投影行数有上限** | 已实现: 折叠投影 `take(60)`, 超出显式标注「另有 N 行未显示」 |
| OB-3 | **单行文字有上限** | 已实现: 普通行 40 字(`fold::LINE_CAP`), 折叠头行 24 字(`HEAD_CAP`) |
| OB-4 | **历史不按步数增长** | 已实现: 旧页折成单行里程碑, 当前页全量展开(v0.6 Step 2) |
| OB-5 | **预算对模型可见** | 已实现: `budget_line`「预算: 已用 X/Y 次模型调用」每轮注入 |
| OB-6 | **折叠永不藏交互把手** | 已实现: 头行 = 子树中面积最大的文字(人与模型本来就点的锚); 被折内容仍在全量层, `what=` 点名照常吸附 |
| OB-7 | **背景动静如实标注** | 已实现: `noise > 0` 时告知模型「本画面持续在动」, 判定按扣除背景后算 |
| OB-8 | **有界滚动**, 单次调用最多滑 `max_swipes` 屏, 一屏无新内容立即停 | **本 PR 新增**: `collect.rs` |
| OB-9 | **重叠读取去重**, 相邻两屏的重叠条目按文字全等去重 | **本 PR 新增**: `collect.rs` |
| OB-10 | **覆盖边界如实回报**: 停在预算还是停在末尾, 必须写清楚, 不假装采完 | **本 PR 新增**: `collect.rs` 的 `coverage.{complete,stop,note}` |
| OB-11 | **MCP 返回同时给文本与结构化内容**, 两边同一份事实 | **本 PR 新增**: `serve.rs::tool_result_payload` |

### 关于 OB-6 的性质

折叠是**投影**, 不是**过滤**。这是本契约里最容易被违反、后果也最严重的一条:
如果折叠把可交互元素藏进缝里, 模型会看到一个「不存在按钮」的页面, 然后开始瞎点。
所以折叠规则的每一道缝都必须有账(折 N 条 M 字), 且被折内容必须在全量层可被点名吸附。

## 2. 组合动作原语: `collect`

零 Token。两个模式:

```bash
# 滚动查找: 命中即停, 回报位置
phonefarm collect --query "关于我们" --max-swipes 8

# 列表采集: 采到列表末尾或有界上限
phonefarm collect --max-swipes 12 --json
```

参数:

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `--serial` | 自动 | 设备; 带 `hdc:` 前缀走 OpenHarmony |
| `--query` | 无 | 给定时为查找模式, 不给为采集模式 |
| `--max-swipes` | 12 | **有界上限**, 超出即标 `max_swipes` |
| `--max-items` | 400 | 返回里保留的条目上限(计数不受此限) |
| `--settle-ms` | 600 | 每滑一屏后的稳定等待, 防惯性滚动没停就读 |
| `--json` | 关 | 输出 JSON |

退出停止原因(`coverage.stop`):

| stop | `complete` | 含义 |
| --- | --- | --- |
| `found` | true | 查到目标文字, 已回报位置 |
| `end_of_list` | true | 某一屏没有任何新内容 —— 到底了 |
| `max_swipes` | **false** | 撞到滑动预算, **下方可能还有未采集内容** |
| `max_items` | **false** | 撞到条目上限 |

`complete=false` 时 `coverage.note` 必须给出人话说明; 这是 OB-10 的落点:
**宁可说「没采完」, 不许说「采完了」**。

### 与失败重放的关系

`collect` **不重放**。它滑一屏、读一屏、记一屏; 一屏没有新内容就停。
这与 iPhone-use 的失败语义同源: 动作超时或断线可能留下**不确定**状态,
盲目重放点击/输入/提交会让不确定变成错误。宁可停在这里, 把边界交给调用方判断。

## 3. 结构化返回(MCP)

`phonefarm serve` 的每个工具现在同时返回:

```json
{
  "content": [{"type": "text", "text": "…原文…"}],
  "structuredContent": { …解析得出的对象… },
  "isError": false
}
```

- 文本给人/模型读, `structuredContent` 给看板与程序消费 —— **同一份事实, 不各自渲染**。
- 子调用输出不是 JSON 对象时, `structuredContent` 缺席(截断/报错文本仍然给全)。
- MCP 规范要求 `structuredContent` 是对象, 所以数组与标量一律只给文本。

### 子调用超时

查看类子调用沿用 30s 上限; `phonefarm_collect` 按滚动预算放宽, 但**不得超过 60s**
(MCP 单次 `tools/call` 约定)。客户端传超大 `max_swipes` / `settle_ms` 也会被夹在上限内 ——
预算两端都要夹, 否则一个工具就能把 serve 拖成挂死。

## 4. 零 Token 与判定口径的边界

`collect` 产出的是**清单**, 不是**结论**。它:

- 不调用任何模型;
- 不做判定、不写经验库(`lessons`)、不动假设/预测/能力库;
- 不碰 `AGENTS.md` 里那条硬边界 —— 判定口径与阈值仍然只能在判定那一侧、在看到候选数据之前冻结。

采集结果若要进入判定, 必须走既有的记录契约(`log.jsonl`)与判定链, 与其它证据同等对待。
